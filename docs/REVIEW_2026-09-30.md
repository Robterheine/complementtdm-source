# Four-perspective review — mAb TDM v0.43.0

**Date:** 2026-09-30. **Reviewed:** `src/*.js`, `src/app.css`, `index.html` (template), the three
control streams, the built `complementtdm.html`. **Lenses:** a bug-averse HTML/JS engineer, a
statistician, a pharmacometrician, a novice MIPD technician.

**Method.** Every finding below marked *verified* was reproduced, either by running the engine in
Node or by driving the **built app in a real browser** through its own forms (dose/sample submit
handlers, the prior-treatment radio, Run, Import, Export, Print). Findings marked *by reading* were
established from the source only. Nothing in the repo was changed; a temporary
`.claude/launch.json` used for the local test server was removed afterwards.

**Not re-raised** (settled, see memory): ADA, drug switching, PD/exposure–response caveats,
THETA/SIGMA uncertainty, ravulizumab target 150, the crovalimab run05 residual, P = *true* trough
(no assay error), partial-history "third answer". The app's no-dose-recommendation rule held
everywhere I looked.

## 0. Verdict

| Question | Answer |
|---|---|
| **1. Is data processing correct?** | **The numerical core is correct; the input boundary is not yet safe.** Parameters match the control streams exactly, and the ODE/likelihood/posterior code is sound. But two kinds of input reach code that misbehaves: (a) an imported session file can execute script, and (b) an unparseable date freezes the tab. Two data-entry defaults (crovalimab route, projected interval) silently produce a wrong model for the most common novice path. |
| **2. Are statistics correct?** | **Yes, with small calibration issues in the diagnostics display.** Likelihood, M3, Laplace covariance (2H⁻¹), split-R̂, bulk-ESS, batch-means CI and the t-multiplier are all right. The findings are about *interpretation text* (a "re-run" advice that cannot work) and *diagnostic thresholds* that ignore the error model. |
| **3. Is the interface logical and usable?** | **Mostly, and it is visibly well cared for**, but it has a layout bug on phones (≈400 px of blank space in card 1), silent input coercion, no way to edit or undo single rows, and a table that is not sorted. |
| **4. Missing features?** | A short list of *data-entry* features dominates (edit row, repeat-dose helper, timing-vs-dose column); none touches the settled model scope. |

**The single most useful structural observation:** the suite has 1 525 assertions and **none of them
executes `ui.js`** (30 suites read it as text; 0 use a DOM). Both engine-boundary bugs below and the
XSS are precisely the class that a text-matching suite cannot see. A ~100-line jsdom smoke harness
(import → run → render) would have caught all three.

## 2. Engineering (HTML / JS)

### H1 — An imported session file can execute script *(High, verified)*
`esc()` (`ui.js:183`, and copies in `diagnostics.js:26` / `chart.js:47`) escapes `& < >` but **not
`"` or `'`**, and several imported values reach `innerHTML` with no escaping at all. Session files
are exactly what colleagues email each other ("hand to a colleague", Getting started).

Reproduced in the built app through the real **Import session** control with a crafted file:

| Field in the JSON | Sink | Result |
|---|---|---|
| `doses[].amt` = `"900<img src=x onerror=…>"` | `renderDoses` → `'<b>' + d.amt + '</b>'` (`ui.js:1539`) | **script ran** (`window.__xss_amt === 1`) |
| `obs[].note` = `x" autofocus onfocus="…" data-y="` | `renderObs` → `value="' + esc(o.note) + '"` (`ui.js:1579`) | attribute breakout confirmed: `autofocus`, `onfocus`, `data-y` injected onto the `<input>` |
| `lloq` = `"<img …>"` | `ui.js:1371` and `:1568` | unescaped sink, by reading |

Why it matters here: the page is served from `robterheine.github.io`, where `localStorage` holds the
autosaved sessions (patient code is stripped, but doses, weights and levels are not), and the header
promises "No data are stored or processed online".

**Fix (small, surgical).**
1. `esc` also escapes `"` → `&quot;` and `'` → `&#39;` (one line, three copies).
2. Validate at the import boundary, not at each sink: `t` must be finite, `amt` a finite number
   > 0, `route ∈ {null,'iv','sc'}`, `dur` finite, `c` finite or null, `lloq` finite number; coerce with
   `Number()`; reject the file with one message otherwise.
3. Test: import the payload above and assert no `<img>`/`onfocus` in `#doseTable`/`#obsTable`.

### H2 — A NaN time hangs the engine *(High, verified)*
`simulate()` groups simultaneous events with `while (i < ev.length && ev[i].t === tEv)`
(`model.js:613`). For `tEv = NaN` that test is never true, `i` never advances, and the outer loop
spins forever.

Reproduced: `runFit` with `doses:[{t:0},{t:NaN},{t:28}]` was still running after 40 s; the same
input through the UI (an imported dose whose date does not parse, so `Date.parse → NaN`) **froze the
browser tab** and the tool had to close it. Observations are safe (`runFit` filters `isFinite(o.t)`);
doses are not. The F21 guard (`Math.abs(tv) > 1e5`) is false for NaN.

Other bad values were harmless (`amt:null`, negative `amt` with a bogus route, string amounts,
`c:NaN` all ran and returned).

**Fix.** In `runFit`, next to the F21 check: `if (allTimes.some(tv => !isFinite(tv) || Math.abs(tv) > 1e5)) throw …`. Belt-and-braces: `simulate()` throws on a non-finite event time. Pair with H1's import validation.

### D1 — DST drift in synthesised dates *(Low, verified)*
Steady-state doses and the assumed / projected dose are placed at `t0 + k·I·86 400 000 ms`. In the
live steady-state run the trough table read `11 Oct 2026, 09:00` then **`25 Oct 2026, 08:00`**
(Europe's clocks go back on 25 Oct), and the printed report repeats it. Display only — PK is correct
— but a clinician will read it as a changed dosing time. Generate the calendar date with
`setDate(getDate()+k·I)` (local wall clock) and convert back to elapsed days for the engine.

### D2 — Hidden state leaks into the export *(Low, verified)*
`state.patient.age` stays set after switching from crovalimab to a drug that hides the field; the
exported eculizumab session contained `"age": 30`. Null it in the drug-switch handler.

### X2 — Tests cannot see the UI *(Process)*
`tests/util.js` loads only `model.js` and `bayes.js`; every `ui.js` test slices source text. That
is honest for the ordering contracts it pins, but H1, H2, U1, U2, U3 and U6 are all invisible to
it. Suggest one jsdom (or Playwright) smoke file: load `complementtdm.html`, import a hostile file,
enter a crovalimab schedule through the forms, run, assert. Keep it separate from the 300-second
engine suites.

*Minor, by reading:* `errorBars` in `chart.js:263` clamps y with `xMin` (copy-paste); it is unused
today. `beforeunload` (`ui.js:1974`) prompts whenever any dose exists, even straight after Export.

## 3. Statistics

**Checked and correct** — each against the source and, where cheap, numerically:
exact Gaussian OFV including the η-dependent `log σ²` term; M3 `−2 log Φ((LLOQ−pred)/σ)`;
Laplace proposal `2·H⁻¹`; Metropolis ratio `−½ΔOFV`; decaying-gain adaptation in the kept phase;
split-R̂ (`varPlus = (n−1)/n·W + B/n`); Vehtari bulk-ESS with Geyer pairs (`τ = −1 + 2ΣΓ`);
type-7 quantiles; batch-means CI with `t₁₁ = 2.201`; `etaInformation = 1 − var_post/var_prior`.
Determinism (identical seed ⇒ identical numbers) was confirmed in the UI.

### T1 — "Re-run" cannot help *(Medium, verified)*
The R̂ advisory says *"…may be unreliable; re-run, or add a sample"* (`ui.js:1403`). The seed is a
constant (`SEED = 20250907`, passed on every run), so re-running reproduces the chain exactly. The
assay-multiplier experiment below returned byte-identical output for identical inputs. Either drop
"re-run", or make the advisory run use a fresh seed (and print it in the report, which today does
not record the seed at all).

### T2 — Residual colours ignore the error model *(Medium, computed)*
`diagnostics.js:33` colours by relative residual (≤30 % green, ≤60 % amber), while the scatter beside
it draws a **±2 SD** band from the actual model. The two verdicts disagree:

| Drug | SD at 150 µg/mL | 30 % in SDs | Consequence |
|---|---|---|---|
| Crovalimab | 17.0 (11.3 %) | **2.65 SD** | a point outside the ±2 SD band is shown green |
| Ravulizumab | 23.2 (15.5 %) | 1.9 SD | roughly consistent |
| Eculizumab at 10 µg/mL | 4.6 (46 %) | 0.65 SD | a +50 % residual is amber while within 1.1 SD |

The header comment's "typical mAb proportional error is 24–30 %" is not true of these three models
(11–16 %). Use IWRES = (obs − ipred)/SD(ipred) with |·| ≤ 2 / ≤ 3 cut-offs, which also makes the
strip agree with the band.

*Small:* the EBE "green = ±40 %" (`diagnostics.js:171`) is not drug-specific. With ω²(CL) = 0.1546
(SD 39 %) a patient with CL +60 % — 1.2 SD, unremarkable — is amber/red; for crovalimab (ω² = 0.0424)
±40 % is ~2 SD. Derive the limits from each drug's ω. And `ebeChart` only shows CL and V1; for
crovalimab the poorly-identified η(KA)/η(F) are the ones a pharmacometrician wants to see.

*Already known, unchanged:* MC-CI across concatenated chains (A5), dead `ess()` (A6).

## 4. Pharmacometrics

**Transcription is faithful.** THETA, OMEGA (incl. the ravulizumab `BLOCK(2)` covariance 0.0161 and
the eculizumab IOV 0.112 folded for aHUS), SIGMA variances, allometric exponents and reference
weights (70 / 70 / 75 kg), ka age exponent, logit-F, and the IV-vs-SC compartment routing all match
`nonmemcontrolstream.txt`, `ravulizumab.txt`, `crovalimab.txt`. `tools/verify_control_streams.mjs`
passes (max deviation 2.7e-4 %).

### S1 — The projected regimen is the *loading* regimen *(High, verified)*
F7 gated the projection while `doses.length ≤ loadingDoseCount (5)`. It did not implement the audit's
own second clause ("or the last ≥2 spacings disagree → do not auto-project"). With the EMA start —
IV day 1; SC days 2, 8, 15, 22; first 680 mg maintenance on day 29 — the 6th dose exists, the gate
opens, and `modalInterval` still sees 7-day gaps:

| Doses entered | Modal interval used |
|---|---|
| crovalimab, 6 (first maintenance dose just given) | **q7d** |
| crovalimab, 7 | **q7d** |
| crovalimab, 8 | **q7d** |
| crovalimab, 9 | q28d |
| eculizumab weekly ×4 → q14d, 7 doses | **q7d** |

In the live app the crovalimab trough table read: *Day 35, 25 Sept, "assumed dose", 148 [115–196],
P > 99 %* — i.e. 680 mg **weekly**, about 4× the real exposure. The explorer then centres its
candidates on q7d. The tag and caption do say "assumed q7d from the entered history", but that is
the moment most troughs are drawn, and the answer is a falsely reassuring P > 99 %.

Root cause is two-fold: the count gate ignores spacing, and `modalInterval` breaks ties towards the
*oldest* mode (`counts[k] > bestN`).

**Fix.** Skip the auto-projection (and the assumed row) whenever the last two spacings differ — the
F7 text — and break modal ties towards the most recent gap (`>=`). Pin: t = 0,1,7,14,21,28 must not
project q7d.

### P1 — Explorer "steady state" is not steady for slow clearers *(Medium, computed; = B6)*
The explorer simulates `clamp(ceil(200/τ), 3, 30)` cycles. Comparing that trough with 40 cycles:

| Case | Explorer cycles | Shortfall vs true steady state |
|---|---|---|
| ravulizumab 3000 q8w, typical | 4 (224 d) | 3.4 % |
| ravulizumab 3000 q8w, CL × 0.61 | 4 | **12.6 %** |
| ravulizumab 3000 q12w, CL × 0.61 | 3 (252 d) | 9.7 % |
| crovalimab 680 q4w, typical | 8 (224 d) | 5.3 % |
| crovalimab 680 q4w, CL × 0.61 | 8 | **15.8 %** |
| eculizumab 900 q2w, CL × 0.61 | 15 | 5.0 % |

The error is on the conservative side (under-predicts), which is the safer direction for
"can I extend?", but the column is labelled *steady-state*. Size the horizon from the patient's own
terminal half-life (≥ 5 t½, which `terminalHalfLife` already gives per draw) rather than a constant
200 days.

*Other, by reading:* in steady-state mode the explorer's `last` dose is a **virtual future** dose
(up to `3 + ⌊nowRel/I⌋` cycles after the anchor), so a candidate change is applied from there; harmless
for the steady-state column, but the wording "after the last dose" is then not literally true.

## 5. Novice MIPD technician

What works (verified in the browser): the four-step card structure; a disabled Run button that names
what is missing (weight range, age, prior-treatment question); the ⓘ popovers; the undo toast after
"clear all"; a correct Export → wipe → Import round-trip (weight, LLOQ, target, recency preset,
planned regimen, prior answer, a per-dose infusion duration, an excluded sample *and its reason* all
came back); HTML in the report's free-text fields is escaped; the phone chart is legible.

### U1 — Crovalimab: every dose after the first is entered as IV *(High, verified; = F10)*
The Route select is never advanced (`ui.js:1822` is the only read). I added an IV 1000 mg dose then
two 340 mg doses without touching it: the table shows **IV, IV, IV**. The fallback
`state.doses.length === 0 ? ar.first : ar.subsequent` is unreachable because the select always has a
value. An IV 340 mg fit has no absorption and F = 1, so CL and the trough are wrong. The table does
show the route, but nothing flags that a crovalimab dose after the first is IV.
**Fix (F10's own):** add an "Auto" option as default that resolves to first = IV, then SC; or set the
select to SC after the first dose.

### U2 — The assay error multiplier is silently reset *(Medium, verified)*
`readPatient` (`ui.js:485`) keeps the value only when 0.1 ≤ m ≤ 10, otherwise uses 1. No message; the
field keeps showing the typed number. With the eculizumab test case: m = 50 gave output
**identical** to m = 1; m = 3 changed P(day 28) from **96 % to 69 %** and widened the interval to
[56.6–112]. So the field matters and a typo is invisible. Treat it like the trough target: add a
reason to `updateRunReady` ("an assay error multiplier between 0.1 and 10"), or write the clamped
value back and toast.

### U3 — Phone layout wastes ≈ 400 px in card 1 *(Medium, verified, measured)*
At ≤ 700 px `.sess-row` becomes `flex-direction: column` (`app.css:408`), but
`.sess-field { flex: 1 1 128px }` (`:60`) then applies as a **height** basis. Measured at 375 px: the
Trough-target fold is 32 px tall inside a 128 px box; the drug field sits in a 170 px box; the
weight and disease fields in 128 px boxes. Fix: inside the `max-width: 700px` block set
`.sess-field, .sess-field.sess-drug { flex: 0 0 auto; }`.

### U4 — The standard crovalimab start trips the duplicate-dose prompt *(Medium, verified)*
The guard is `|Δt| < 24 h` (`ui.js:1846`). IV loading at 14:00 on day 1 and the first SC dose at
09:00 on day 2 are 19 h apart, which produced *"A dose is already recorded within 24 hours … Is this
really a second, separate dose?"* on the first two doses of every crovalimab start. Users learn to
click through. Suppress it when the routes differ, or narrow to ≤ 6 h for differing routes.

### U5 — Age below the minimum is not explained *(Low, verified)*
Typing 8 for crovalimab shows *"Enter the patient's age to run the forecast."* (v0.39.0 fixed exactly
this for weight.) Name the rule: *"an age of 12 years or more for Crovalimab"*.

### U6 — Measurement-table ergonomics *(Medium)*
- **Not chronological** (verified): a sample added second for an earlier date listed second
  (`28.0` then `22.0`); doses are sorted, samples are not.
- **No duplicate guard** for samples, unlike doses (by reading). The same result entered twice doubles
  its weight in the likelihood and narrows the posterior.
- **No edit**: a dose or sample typo means remove and re-add; **Remove is immediate and permanent**
  (autosaved), only "clear all" has an undo.
- **No timing context**: the table shows the date but not "x h after dose n". The report has that
  ("trough-level (just before dose)") and the function exists; showing it on screen is the cheapest
  guard against a mistyped sample date.

### Text and documentation mismatches *(X1, Low)*
- Getting started promises a **"one-page"** report; the generated one is several pages.
- SS report says "24 doses at 900 mg **q14.0d**" (`fmtC` on an interval); the 24 includes synthesised
  and projected doses, so the number is meaningless to a reader.
- The chart's `desc` (screen-reader text, `ui.js:1166`) prints `Math.round(p·100)` → **"100 %"**,
  contradicting the v0.42.0 "> 99 %" rule used everywhere else.
- The report prints the informativeness figures twice (a text row and the bar table).
- Steady-state mode never says how long the regimen must have been unchanged. A sentence per drug
  (t½-based: roughly 2–3 months eculizumab, ~6 months ravulizumab) would stop a recent change being
  entered as steady state.

## 6. Missing features (none touches the settled model scope)

Ordered by value to a real ward, and none of them recommends a dose:

1. **Edit row** for doses and samples (and per-row undo). Removes the highest-friction step.
2. **Repeat-dose helper**: "N doses every X days from <date>" for a loading series or an 18-month
   q2w history. Pairs with the CSV/paste idea already in the 2026-09-29 review (C11).
3. **Timing column** on the sample table (hours after / before the nearest dose) with a soft flag when
   a sample labelled trough is > 1 h from a dose (date typos).
4. **Fresh-seed re-run** and the seed printed in the report, so a convergence warning has an action.
5. **Results export** (CSV of the trough table, posterior summaries) for QA and audit; the session
   JSON carries inputs only.
6. **Standardised residuals** (IWRES) and, for crovalimab, all six η in the EBE panel (T2).
7. **Plasma exchange / CRRT**: the exclude flag handles a *sample* drawn afterwards, but the forecast
   still carries on as if no drug were removed. Not a model change; a one-line, visible statement of
   the scope would do (your call — it is neither ADA nor PD).
8. *Already on the 2026-09-29 list, still open:* touch/keyboard reachable chart tooltip (C4); explorer
   horizon (B6 = P1 here); bulk entry (C11).

## 7. Suggested order of work

1. **H2 + H1 together** (one import-validation function, one `esc` change, a NaN guard in `runFit`),
   with the jsdom smoke test that would have caught both. Small, all in `ui.js` / `model.js` /

   one-function fixes with a clear pin test, and both remove a falsely reassuring output.

4. **T1, D1, D2, X1** wording and small correctness.
5. **T2 / P1 / U6 / features** as time allows.

Every fix should follow the repo's golden rule 7b: write the assertion, watch it fail on the current
code, then fix. All reproduction recipes above use only the built file plus its own form controls
(or `tests/util.js`), so they can be turned into those assertions directly.
